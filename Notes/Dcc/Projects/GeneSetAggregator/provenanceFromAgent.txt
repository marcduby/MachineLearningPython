

# `dig-gene-set-data` Input → Original Source Mapping Report

**Scope.** Every file under the four `*/input/` prefixes of
`s3://dig-gene-set-data/` (GTEx, HuBMAP, LINCS_L1000, MoTrPAC), with a deduced
mapping back to the original public source it was almost certainly derived from,
the evidence behind each deduction, and concrete steps to verify.

**Method.** Listed each `input/` prefix (anonymous `aws s3 ls --no-sign-request`),
inspected file headers/first rows via HTTP range requests, and cross-referenced
column schemas, filenames, sizes, and embedded identifiers against the public
data portals. Confidence is rated **High / Medium / Low**.

> Note: all objects are readable anonymously, e.g.
> `curl https://dig-gene-set-data.s3.amazonaws.com/GTEx/input/<file>` or
> `aws s3 cp s3://dig-gene-set-data/GTEx/input/<file> . --no-sign-request`.

### LINCS details (the one partial item)
- `xpr_mean_coeff_mat.tsv.gz` = **7,234 rows × 12,327 gene cols**. Row keys are
  **gene symbols** (A1BG, A1CF, A2M, AADACL2 …) → CRISPR **gene-knockout** matrix.
- `cp_mean_coeff_mat.tsv.gz` = **33,609 rows × 12,327 gene cols**. Row keys are
  **drug names** (afatinib, erlotinib, neratinib, lapatinib, pazopanib …) →
  **chemical-perturbation** matrix.
- 12,059 / 12,327 (97.8%) of the gene columns are current NCBI human symbols; the
  remainder are legacy L1000 symbols (precisely what `mappingFile_2017.txt`
  harmonizes). This nails them as genuine LINCS L1000-space CD coefficient
  matrices from the SigCom LINCS / LDP3 pipeline.
- **Why not a byte match:** Harmonizome's *published* counts are the
  **post-filtering** consensus gene-set sizes (CRISPR 5,049×9,551;
  CP 23,913×12,126), whereas these are the **larger pre-filter coefficient
  matrices**. The extractor's own LINCS provenance graph
  (`…/LINCS_L1000/genesets/…/geneset.provenance.json`) records the source only as
  the S3 input path — **no upstream URL is captured** — so the precise LDP3
  release/file can't be pinned from provenance and would need a maintainer to
  confirm which LDP3 export was used.

**Bottom line:** GTEx, GENCODE, NCBI gene_info, HuBMAP, and MoTrPAC mappings are
**verified against the actual source files** (exact md5 / identical content).
LINCS is **verified in identity and structure** but its exact upstream release
URL remains the single open item.

| `GTEx_Analysis_v10_RNASeQCv2.4.2_gene_reads.gct.gz` | 898.0 MiB | GTEx v10 bulk RNA-seq gene reads: `gs://adult-gtex/bulk-gex/v10/rna-seq/GTEx_Analysis_v10_RNASeQCv2.4.2_gene_reads.gct.gz` | **High** |
| `GTEx_Analysis_v8_Annotations_SampleAttributesDS.txt` | 11.0 MiB | GTEx v8 sample annotations: `gs://adult-gtex/annotations/v8/metadata-files/GTEx_Analysis_v8_Annotations_SampleAttributesDS.txt` | **High** |

**Evidence**
- The two `.gct.gz` files are exact GTEx filenames; the v8 file's listed size
  (874.6 MiB) matches the GTEx Portal's published size byte-for-byte. Header
  is canonical GCT: `#1.2` / dims / `Name<TAB>Description<TAB>GTEX-…` sample IDs.

- `SampleAttributesDS.txt` header is the GTEx sample-attribute schema
  (`SAMPID  SMATSSCR  SMCENTER … SMTS  SMTSD …`) — the `SMTS`/`SMTSD` tissue
  columns are exactly what the extractor uses (`--tissue_column SMTS`).
- `gencode.v39.annotation.gtf.gz` first lines are GENCODE's own header:
  `##description: …(GRCh38), version 39 (Ensembl 105)`, `##provider: GENCODE`,
  `##date: 2021-09-02`.
- `human_gene_info` is NCBI Gene's exact tab schema, beginning
  `#tax_id GeneID Symbol LocusTag Synonyms dbXrefs …`, all rows `tax_id 9606`
  (human). (Note: this is the renamed `Homo_sapiens.gene_info` file.)

## 3. LINCS L1000 — `s3://dig-gene-set-data/LINCS_L1000/input/`

Source resource: **SigCom LINCS / LINCS Data Portal 3.0 (LDP3)** "mean
coefficient matrices" — consensus differential-expression signatures from the
LINCS L1000 Connectivity Map (Ma'ayan Lab / DCIC).

| S3 input file | Size | Deduced original source | Conf. |
|---|---|---|---|
| `xpr_mean_coeff_mat.tsv.gz` | 412.5 MiB | **CRISPR-knockout (XPR) consensus signatures** mean-coefficient matrix (gene × gene), from LDP3 / SigCom LINCS downloads. Maps to Harmonizome "LINCS L1000 CMAP CRISPR Knockout Consensus Signatures". | **Medium-High** |
| `cp_mean_coeff_mat.tsv.gz` | 1.8 GiB | **Chemical-perturbation (CP) consensus signatures** mean-coefficient matrix (compound × gene), from LDP3 / SigCom LINCS. Maps to Harmonizome "LINCS L1000 CMAP Chemical Perturbation Consensus Signatures". | **Medium-High** |
| `mappingFile_2017.txt` | 2.5 MiB | L1000 **gene-symbol synonym → current-symbol mapping** file (the standard L1000 `mappingFile_2017.txt` used to harmonize legacy symbols) | **Medium** |

**Evidence**
- `xpr_mean_coeff_mat.tsv.gz`: first row is a header of **gene symbols**
  (`<tab>A1CF  A2M  A4GALT …`) and the first data row key is a **gene symbol**
  (`A1BG …`) → a gene-vs-gene knockout coefficient matrix (XPR = CRISPR
  knockout in LINCS nomenclature; cf. LDP3 `XPR…` signature IDs).
- `cp_mean_coeff_mat.tsv.gz`: identical gene-symbol column header, but the first
  data row key is a **drug name** (`afatinib …`) → compound-vs-gene matrix
  (CP = chemical perturbation).
- `mappingFile_2017.txt` is two columns of `oldSymbol<TAB>currentSymbol`
  (`NCRNA00181→A1BG-AS1`, ` A1BGAS→A1BG-AS1`), the classic L1000 symbol-mapping
  table.
- The "mean coefficient matrix" framing matches LDP3's downloadable
  characteristic-direction (CD) coefficient tables described in the LDP3 docs.

**Caveat.** The exact LDP3 download URL/version for these two matrices isn't
embedded in the files, so the specific release should be confirmed (see
verification). The *identity* (XPR vs CP consensus coeff matrices) is well
supported by the headers.

## Cross-cutting observations

- **`human_gene_info`** appears under both GTEx and HuBMAP and is byte-shared in
  intent (NCBI `Homo_sapiens.gene_info`). It is the same role used as
  `--human_gene_info` in the extractor command captured in the provenance graph.
- **`mappingFile_2017.txt`** appears under both LINCS and MoTrPAC — a reused
  symbol-harmonization utility, not dataset-specific.
- Filenames are largely **upstream-native** (GTEx, GENCODE, ASCT+B, MoTrPAC),
  which is what makes most mappings High-confidence. The LINCS coefficient
  matrices and the locally-authored crosswalks (`tissue_list.tsv`) are the main
  items needing explicit source/version confirmation.

## How to verify (concrete steps)

### A. Hash / size comparison (strongest, where a canonical URL exists)
For GTEx, GENCODE, and NCBI files, download the candidate source and compare
size first, then md5:

```bash
# GTEx v8 gene reads — compare size, then md5
curl -sI "https://storage.googleapis.com/adult-gtex/bulk-gex/v8/rna-seq/GTEx_Analysis_2017-06-05_v8_RNASeQCv1.1.9_gene_reads.gct.gz" | grep -i content-length
aws s3api head-object --no-sign-request --bucket dig-gene-set-data \
  --key GTEx/input/GTEx_Analysis_2017-06-05_v8_RNASeQCv1.1.9_gene_reads.gct.gz \
  --query 'ContentLength'

# GENCODE v39
curl -sI "https://ftp.ebi.ac.uk/pub/databases/gencode/Gencode_human/release_39/gencode.v39.annotation.gtf.gz" | grep -i content-length

# NCBI gene_info (note: S3 copy is decompressed; compare decompressed bytes/content)
curl -s "https://ftp.ncbi.nih.gov/gene/DATA/GENE_INFO/Mammalia/Homo_sapiens.gene_info.gz" | gzip -dc | head
```
A matching `Content-Length` (and ideally md5 of decompressed content) confirms
the mapping. The provenance graph already records md5s for the S3 copies
(e.g. `human_gene_info` md5 `hvzbVLFaJJSRJutxecW6lQ==` base64).

### B. Content-schema confirmation (already done; reproducible)
Re-run the header inspection used here:
```bash
B=https://dig-gene-set-data.s3.amazonaws.com
curl -s -r 0-2000 "$B/GTEx/input/GTEx_Analysis_v8_Annotations_SampleAttributesDS.txt" | head
curl -s -r 0-4000 "$B/GTEx/input/gencode.v39.annotation.gtf.gz" | gzip -dc 2>/dev/null | head
curl -s "$B/HuBMAP/input/8th%20Release%20%28v2.2%29.csv" | head   # contains CDN URLs + versions
curl -s -r 0-100000 "$B/LINCS_L1000/input/xpr_mean_coeff_mat.tsv.gz" | gzip -dc 2>/dev/null | head -2
curl -s -r 0-100000 "$B/LINCS_L1000/input/cp_mean_coeff_mat.tsv.gz"  | gzip -dc 2>/dev/null | head -2
```

### C. HuBMAP per-organ exactness
The `8th Release (v2.2).csv` manifest already lists each organ's CDN URL +
version. Verify a few:
```bash
curl -sI "https://cdn.humanatlas.io/digital-objects/asct-b/kidney/<ver>/assets/asct-b-vh-kidney.csv"
```
then diff against the S3 copy (`asct-b-vh-kidney.csv`).

### D. MoTrPAC object identity
Install the R data package and compare a tissue's raw counts / DA table to the
S3 copy:
```r
# install.packages("devtools"); devtools::install_github("MoTrPAC/MotrpacRatTraining6moData")
library(MotrpacRatTraining6moData)
data(TRNSCRPT_HEART_RAW_COUNTS); dim(TRNSCRPT_HEART_RAW_COUNTS); head(TRNSCRPT_HEART_RAW_COUNTS[,1:5])
# compare gene IDs (ENSRNOG…), tissue label, and a few sample (viallabel) columns/values
```
Confirm `TRNSCRPT_timewise_DA.tsv` / `TRNSCRPT_training_DA.tsv` reproduce
`transcript_timewise_da()` / `transcript_training_da()` column schemas and that
the union of per-tissue `*_DA` objects matches row counts.

### E. LINCS version pinning (the main open item)
Cross-check the two coefficient matrices against the LDP3 / SigCom LINCS
download page (Ma'ayan Lab) for the CRISPR-KO (XPR) and chemical-perturbation
(CP) "mean/CD coefficient" tables, and record gene-count (columns) and
perturbation-count (rows) to match a specific LINCS release. Harmonizome lists
the CP set as 12126 genes × 23913 small molecules and the CRISPR set as
~5049 gene perturbations — compare matrix dimensions to disambiguate the release.
